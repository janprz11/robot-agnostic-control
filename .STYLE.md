# STYLE.md

This file describes the style that should be adhered to when writing Python files.

## Command Line Interfaces

- Use argparse for command line parsing.
- Define a `parse_args` function that returns `dict[str, Any]`.
- Call `parse_args` in the `if __name__ == "__main__"` block and pass the result to `main(args: dict[str, Any] = dict())`.
- Error messages that do not raise an exception use `print("ERROR: ...")` format.

## Comments

- Do not use docstrings.
- Except for docstrings, comments should start with a lowercase letter and are not full sentences. However, they should still use proper articles.
- Use semicolons to separate different parts of a comment if needed.
- Inline comments have two spaces before the `#`.
- Use single-line comments to describe what a block of code does, written in present tense.

## Configuration

- Use JSON files for templates and similar configuration data.

## File Structure

- Executable scripts start with a shebang (`#!/usr/bin/env python` or `#!streamlit run`).
- All files include `# -*- coding: ascii -*-` on line 1, or line 2 if a shebang is present.
- A blank line separates the encoding declaration from the imports.
- Module-level assertions for critical invariants appear immediately after imports.

## Formatting

- Use Python Black.
- A blank line appears before a block comment only when the previous line is at the same or greater indentation level.

## Imports

- Sort imports alphabetically by module name in a single block without separating by category.
- When both `import x` and `from x import y` exist for the same module, the `import x` form comes first.
- Never import `List`, `Dict`, or `Tuple` from typing; use the built-in `list`, `dict`, and `tuple` instead.

## Naming

- Classes use `PascalCase`.
- Functions, methods, and variables use `snake_case`.
- Constants use `UPPER_SNAKE_CASE`.
- Private members use a single underscore prefix.

## Ordering

- Classes, functions, and methods are ordered alphabetically.

## Strings

- Use double quotes for all strings.
- Single quotes are only used when the string contains double quotes.
- Use f-strings for all interpolation.

## Type Hints

- All function signatures must have type hints including return types.
- Use modern syntax like `list[str]` and `dict[str, int]`.
- For optional types, use `str | None` rather than `Optional[str]`.
- For mutable defaults, use `list()` or `dict()` instead of `[]` or `{}`.
